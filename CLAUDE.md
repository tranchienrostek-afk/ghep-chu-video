## Memory Flow OS — project continuity anchor

Conversation context is temporary; repository memory + Git are durable memory.
Start/resume from `docs/memory/00-control/MAP.md`, then `docs/memory/10-current/`, then follow only task-relevant branches.
For substantial work use: **LOCATE → RECONSTRUCT → CHANGE → VERIFY → RECORD → CONTINUE**.
Before rebuilding anything that seems missing, inspect current code, Git history, branches/tags, deleted paths, decisions, checkpoints, roadmaps, and diagrams.
Before substantive commits, close memory in `STATE.md` + `NEXT.md` and record ADR/checkpoint/evolution changes when warranted.
Do not depend on the human to remind you. Use the `memory-flow` skill automatically for startup/resume, architecture changes, commits, recovery, compaction, checkpoints, and long-horizon work.
