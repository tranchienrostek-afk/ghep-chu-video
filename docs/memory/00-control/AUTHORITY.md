# Authority Model

There is no single flat source-of-truth order for every question. Use the authoritative evidence for the type of claim.

## Current executable behavior

1. observed runtime / reproducible test
2. current code and configuration
3. current-state documentation

## Intended architecture, policy, or contract

1. accepted ADR / approved spec or contract
2. current architecture/domain documentation
3. current-state summary
4. old roadmap or historical notes

## Current work continuity

1. `10-current/STATE.md`
2. `10-current/ACTIVE_WORK.md`
3. `10-current/ACTIVE_ROADMAP.md`
4. `10-current/NEXT.md`
5. current Git working tree/status

## Historical truth

1. Git commits/trees/tags/branches
2. semantic checkpoint records
3. timeline/failure records

## Conflict rule

A disagreement is evidence, not permission to pick the convenient version. Investigate and record the resolution. Never silently rewrite history to make the present look inevitable.
